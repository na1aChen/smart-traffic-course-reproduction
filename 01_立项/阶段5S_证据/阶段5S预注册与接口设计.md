# 阶段 5S 预注册与接口设计

| 字段 | 内容 |
| --- | --- |
| 实验编号 | `SYS5S-001` |
| 日期 | 2026-11-10 |
| 执行人 | 本人；Codex 辅助执行与复核 |
| 类型 | 检测计数到流量预测的离线模块级联原型 |
| 检测模型 | `BASELINE-001`，YOLOv10-N |
| 预测模型 | 第一次大作业的 TA-iTransformer `pl96` checkpoint |
| 修改状态 | 运行前预注册；若执行规则变化，必须另起版本并说明 |

## 一、目的

验证课程高阶要求中的两个模块能否形成一次可复算的数据链：

1. 检测模块输出结构化目标结果；
2. 适配层把检测结果转换为预测模型可读取的固定形状输入；
3. 预测模块加载已有 checkpoint 并输出未来序列；
4. 保留每一步的输入、输出、来源、哈希和限制说明。

本实验只证明“模块可连接并运行”，不证明真实交通态势预测效果提升。

## 二、可复用资产

| 资产 | 路径 | 用途 |
| --- | --- | --- |
| 检测事件表 | `03_实验/诊断/BASELINE-001/analysis/test_pred_events.csv` | 图像 ID、类别、置信度、框 |
| 预测数据 | `第一次大作业/.../dataset/PEMS/PEMS08.npz` | PEMS08，170 个传感器、5 分钟采样 |
| 预测 checkpoint | `第一次大作业/.../checkpoints/.../checkpoint.pth` | 已训练的 `sl96/pl96` TA-iTransformer |
| 预测源码 | `第一次大作业/.../smart_traffic_itransformer_run_20261022` | 模型结构、数据切分和评估口径 |

复用边界：

- 不重新训练检测模型；
- 不重新训练 iTransformer；
- 不修改检测权重或预测权重；
- 不把历史 checkpoint 的训练结果包装成本次 5S 的新训练结果。

## 三、数据流

```text
TT100K 测试图像
  -> BASELINE-001 检测结果
  -> 结构化事件表
  -> 按图像 ID 顺序分成 96 个箱
  -> 每个箱聚合检测数与置信度和
  -> 标准化为 96 步检测计数代理曲线
  -> 替换 PEMS08 测试窗口第 169 通道
  -> TA-iTransformer checkpoint
  -> 96 步、170 通道预测序列
```

“图像 ID 顺序”不是时间顺序。TT100K 图像不是连续时间序列，因此代理曲线的横轴只用于满足预测模型长度要求，不能解释为真实时间戳。

## 四、接口字段

### 4.1 检测模块输出

每条事件至少包含：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `image_id` | 字符串/整数 | 样本 ID |
| `predicted_class_id` | 整数 | 预测类别编号 |
| `predicted_class` | 字符串 | 类别名称 |
| `pred_score` | 浮点数 | 检测置信度 |
| `pred_box` | 四元数组 | `[x, y, width, height]`，TT100K 原图像素坐标 |
| `split` | 字符串 | 数据划分 |

### 4.2 适配层输出

- `detector_bins.csv`：96 行，每行的字段为箱号、图像 ID 范围、图像数、检测数、置信度和；
- `detector_proxy`：长度 96 的标准化浮点序列；
- `pems_input`：`96 x 170` 标准化输入；
- `injected_channel`：固定为第 `169` 通道；
- `valid_as_time_series`：固定为 `false`；
- `mapping_type`：固定为 `image_id_order_proxy`。

### 4.3 预测模块输出

- `prediction`：`96 x 170`；
- `baseline_prediction`：同一窗口、不注入代理时的 `96 x 170` 预测；
- `prediction_steps`：96；
- `prediction_channels`：170；
- `checkpoint_loaded`：布尔值；
- `model_metrics_reproduced`：布尔值；
- `chain_type`：`offline_module_cascade_prototype`。

## 五、固定执行规则

1. 检测数据取 `test_pred_events.csv` 中非空预测框、`predicted_class_id >= 0` 的事件；
2. 按数值升序排列唯一 `image_id`；
3. 用等频分箱方法分成 96 箱，最后一箱吸收余数；
4. 每箱代理值先取置信度和，再做零均值、单位标准差标准化；
5. PEMS08 取 `data['data'][:,:,0]`，按 60%/20%/20% 切分；
6. 标准化器只在训练段拟合；
7. 联调示例使用测试段第 0 个窗口；
8. 模型输入长度 96、预测长度 96、170 通道；
9. 用检测代理替换第 169 通道，不增加模型参数；
10. 预训练模型完整测试集推理只用于核验 checkpoint 与旧参考指标一致，不用于调参。

## 六、核验指标

### 6.1 模块级核验

| 检查 | 通过条件 |
| --- | --- |
| 检测事件可读 | 事件数大于 0，必需字段齐全 |
| 代理形状 | 长度严格等于 96 |
| 输入形状 | 严格等于 `96 x 170` |
| checkpoint 加载 | `load_state_dict` 严格模式无缺失/多余键 |
| 预测形状 | 严格等于 `96 x 170` |
| 预测数值 | 全部为有限值 |
| 注入生效 | 基准与注入预测存在非零差分 |
| 完整测试复算 | MSE/MAE 与旧参考值在 `1e-4` 内一致 |

### 6.2 描述性差异

记录：

- 基准预测与注入预测的平均绝对差；
- 注入相对基准的预测变化率；
- 第一窗口在 PEMS08 上的 MSE 和 MAE。

这些数值只说明“输入改变确实传播到了输出”，不能解释为模型变好或变差。

## 七、允许与禁止的结论

允许：

- “已完成一次检测计数到流量预测的离线模块级联运行”；
- “checkpoint 可加载，预测输出可复算”；
- “检测代理与 PEMS08 不存在真实时空对齐，因此系统只验证接口”；
- “零重训通道替换是工程适配器，不是训练好的多模态融合模型”。

禁止：

- 声称完成真实端到端交通态势验证；
- 声称检测结果提高了 PEMS08 预测精度；
- 把图像 ID 顺序写成真实时间顺序；
- 把复用 checkpoint 的历史 MSE/MAE 写成本次新模型训练结果；
- 删除或隐藏失败案例、依赖异常和数据错位限制。

## 八、停止条件

出现以下任一情况时，降级为“接口设计与可加载性检查”，不强行完成联调：

- checkpoint 无法严格加载；
- 预测源码与现有 PyTorch 不兼容；
- 依赖安装会升级现有 CUDA PyTorch；
- 完整测试推理无法在 22:30 前结束；
- 需要修改已冻结的检测或预测权重。
