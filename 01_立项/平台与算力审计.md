# 平台与算力审计

本文件记录 2026-11-07 的本机只读审计结果。它用于限定阶段 1 和阶段 2 的可行方案，不把尚未运行训练时的估算写成实验结果。

## 一、硬件与环境

| 项目 | 实测值 | 对项目的影响 |
| --- | --- | --- |
| CPU | Intel Core i9-12900HX，16 核 24 线程 | 可用于数据预处理和轻量评估，训练仍以 GPU 为准 |
| 内存 | 15.7 GiB 可用物理内存 | DataLoader worker、batch size 和缓存不能开得过大 |
| GPU | NVIDIA GeForce RTX 4060 Laptop GPU，8188 MiB 显存 | 适合 YOLOv10-N 或 YOLOv8n/s；不适合大模型全参数训练 |
| GPU 驱动 | 595.79，计算能力 8.9 | 支持通过 PyTorch 官方 GPU wheel 使用 CUDA |
| 默认 `python` | Python 3.11.15，路径为 Codex/hermes 管理环境 | 没有安装 Torch，不能用于本项目的正式训练 |
| `py -3.10` | Python 3.10.6，路径为 `<LOCAL_USER>\AppData\Local\Programs\Python\Python310\python.exe` | 满足 YOLO 仓库常见版本要求，但不应直接污染全局环境 |
| 当前 PyTorch | 在 `py -3.10` 环境中为 2.12.0+cpu；默认 `python` 未安装 Torch | `torch.cuda.is_available()` 为 `False`，当前环境不能做 GPU 训练 |
| 磁盘 | D 盘剩余约 139.2 GiB，C 盘剩余约 213.9 GiB | 可容纳原始数据、解压数据和若干实验产物，但必须统一数据根目录 |

本机没有可用的 `nvcc`。这不妨碍使用预编译 PyTorch GPU wheel；阶段 1 应使用 `py -3.10 -m venv` 建立项目独立环境，再安装与驱动兼容的 GPU wheel，不应为了“安装完整 CUDA Toolkit”额外扩大环境风险。当前也未安装 Ultralytics。

## 三、训练预算

当前配置的保守方案是：

| 参数 | 初始值 | 说明 |
| --- | --- | --- |
| 主模型 | YOLOv10-N | 约 2.3M 参数、6.7G FLOPs，显存压力最低 |
| 输入尺寸 | 先 512 或 640 做 smoke test，再锁定训练尺寸 | 不使用未经验证的高分辨率堆叠 |
| 精度 | AMP/FP16 允许则打开 | 必须保留关闭 AMP 的失败排查入口 |
| batch size | 4 到 8 起步，由实测显存决定 | 不追求把 8 GiB 显存填满 |
| DataLoader workers | 2 到 4 起步 | Windows 下同时关注内存和进程启动开销 |
| 随机种子 | 初测固定为 42，正式对比统一口径 | 多种子另行安排 |
| 首个门槛 | 5% 训练子集或 1 个 epoch 的 smoke test | 通过后才启动完整基线 |

阶段 2 必须先测量每秒图像数、单 epoch 用时和峰值显存，再决定正式 epoch 数。不能先写“训练 100 epoch”，最后因时间不足悄悄减少预算。

## 四、风险与降级

| 风险 | 触发条件 | 降级动作 |
| --- | --- | --- |
| CUDA 环境不可用 | PyTorch 无法识别 GPU | 在独立虚拟环境安装与驱动匹配的 PyTorch GPU wheel；CPU 训练不作为正式实验 |
| 显存不足 | batch 4 仍 OOM | 降低输入尺寸、batch 或启用梯度累积；记录变化 |
| 完整数据训练过慢 | 单 epoch 预计无法在时间盒内完成 | 使用预先固定的 10 到 12 类子集，保留完整划分文件，不动态挑样本 |
| 2021 数据包格式与代码不兼容 | 标注字段或类别 ID 不一致 | 回到阶段 1 检查官方代码与标注格式，不直接开始训练 |
| 存储不足 | 解压后空间低于 30 GiB | 清理临时副本前先核对绝对路径；只保留可追溯的原始包和解压数据 |

本机具备完成基础任务的硬件条件，但当前软件环境不具备 CUDA 训练能力，因此阶段 1 的“环境可运行”仍是硬门槛，不能以平台审计代替 smoke test。
