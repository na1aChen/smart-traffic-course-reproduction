# 全流程执行计划

本计划依据课程方法论文档制定。流程按证据门槛推进，不按“感觉快做完了”推进。每个会话只执行一个阶段，最多附带下一阶段的只读准备。

最终截止时间为 **2026-11-22**。阶段总结 Markdown 是阶段退出的必备产物，不是可选的会议纪要。

## 一、总流程

| 阶段 | 目标 | 主要产出 | 进入下一阶段的硬条件 |
| --- | --- | --- | --- |
| 0 立项 | 定问题、范围、完成定义和禁区 | 项目信息卡、执行计划、门槛清单 | 主问题、数据、指标、交付物和“不做什么”写清 |
| 1 来源锁定 | 锁定论文、仓库、版本、数据、环境和模板 | 来源清单、commit SHA、环境快照、数据校验、模板审计 | 任何结果都能追溯到版本 |
| 2 基线复现 | 先证明能运行、指标是多少、差距多大 | 官方命令对照、同配方基线、日志、曲线、指标 | 基线可复算且口径明确 |
| 3 失败诊断 | 找出主要错误机制，不急着“修” | 类别 AP 表、混淆矩阵、尺寸分桶、漏检/误检案例 | 每个拟改进点都有证据对应 |
| 4 单因子改进 | 一次只验证一个改动 | 基线、因子 A；必要时因子 B | 可在同训练配方下复算，结论强度与 seed 数一致 |
| 5 组合与稳健性 | 判断收益是否可信、是否来自额外容量或偶然性 | A+B、对照、不同 seed、必要时第二划分 | 主表有均值/标准差或明确标为单 seed |
| 5S 高阶拓展（条件执行） | 在基础证据稳定后尽量完成识别 + 流量预测原型 | 接口定义、流量预测模块、离线联调、系统演示、边界说明 | 基础任务通过；拓展有实际运行结果；数据拼接方式披露 |
| 6 证据冻结 | 锁定所有数字、图表与来源 | 实验总表、主图、结果说明、异常与负结果清单 | 报告和 PPT 只引用冻结版本 |
| 7 报告 | 基于指定模板完成完整报告 | DOCX、图表源文件、引用表 | 模板、内容、引用和渲染全部通过 |
| 8 PPT 与答辩 | 把同一组事实压缩成可讲述证据链 | PPT、讲稿、五问答案、现场演示 | 2 分钟脱稿、现场推理、指标复算通过 |
| 9 终验 | 从干净路径重跑关键流程 | 环境安装记录、smoke test、主结果复算、交叉一致性检查 | 报告/PPT/代码/实验表一致 |

## 二、分会话推进

| 会话 | 允许完成的内容 | 明确不进入的内容 |
| --- | --- | --- |
| 本次会话 | 阶段 0；完成候选文献、本机算力和模板的只读审计 | 不训练、不下载大数据、不生成最终报告 |
| 第 2 次 | 阶段 1：确定主模型与保守备选，锁定论文、仓库、commit、环境、数据入口 | 不碰测试集结果 |
| 第 3 次 | 阶段 2：数据审计、10+ 类子集、基线 smoke test、完整基线运行 | 不同时改模型 |
| 第 4 次 | 阶段 2 收尾与阶段 3：基线与论文对比、错误分析 | 不在诊断完成前定改进结论 |
| 第 5 次 | 阶段 4：只跑一个可单独关闭的改进因子 | 不同时叠两个因子 |
| 第 6 次 | 阶段 5：组合、负对照、多种子或算力降级实验 | 不把探索结果升级为稳定结论 |
| 第 7 次 | 阶段 5S：在基础门槛通过后，尽量完成流量预测接入与系统演示 | 基础未通过时不得用高阶界面掩盖缺失实验 |
| 第 8 次 | 阶段 6 与 7：证据冻结，生成报告初稿与模板渲染检查 | 不手工改数字绕过实验表 |
| 第 9 次 | 阶段 8：PPT、讲稿、预设问答和脱稿演练 | 不引入报告中没有证据的新数字 |
| 第 10 次 | 阶段 9：干净环境复算、最终版报告与答辩复核 | 不在此阶段大改方法 |

如截止日期更紧，可以合并同阶段的运行批次，但不能跳过门槛。任何压缩都必须同步降低结论强度。

## 三、高阶拓展决策门

第二张图中的样本不足、类别不平衡和实时推理方案已由用户确认为可参考的设计要点，因此优先进入候选假设池。高阶“识别 + 流量预测”按以下规则决定是否启动：

1. 基础任务至少已有可复算基线、错误分析和一个单因子实验。
2. 距离 PPT 冻结节点至少保留一个独立工作单元，不能靠通宵串行修补。
3. 优先复用第一次大作业已验证的交通流预测代码和数据，明确来源与复用边界。
4. 先完成最小结果：检测结果表或计数快照 -> 预测模块输入 -> 预测结果 -> 可视化。
5. 若无法得到与检测图像严格对齐的连续流量数据，只能称为“模块级离线联调原型”，并在报告和 PPT 中披露拼接方式。
6. 若时间不足，降级为系统架构与接口设计，但不得伪造运行结果。

## 四、实验顺序

实验顺序固定为：

```text
数据审计
  -> 官方或官方推荐基线
  -> 同训练配方基线
  -> 错误分析与问题陈述
  -> 单因子 A
  -> 单因子 B（可选）
  -> A+B（可选）
  -> 容量/随机/语义对照（按适用性）
  -> 多 seed
  -> 报告主表
```

每个实验必须有唯一 ID，并保存：

- 数据版本与划分文件。
- 配置文件与命令行。
- 随机种子。
- Git commit 和本地 diff。
- 训练日志与验证曲线。
- 最佳 checkpoint。
- 测试集原始预测和真实标注。
- 总体指标、每类 AP、尺寸分桶、混淆矩阵。
- 运行时长、峰值显存和失败记录。

## 五、每个会话的固定动作

会话开始时：

1. 读取项目信息卡和上一次的交接记录。
2. 确认当前阶段、允许动作和禁止动作。
3. 只读检查上一阶段产出的哈希与状态。

会话结束时：

1. 按 `阶段总结规范.md` 写一份中文阶段总结 Markdown。
2. 列出已完成证据、未解决风险和下一步唯一动作。
3. 只有阶段总结存在且门槛核对后，才能把阶段标记为通过。
4. 若阶段门槛未通过，不修改报告中的结论。
