# 候选模型与技术路线

本文件完成阶段 0 的候选模型比较和初始路线建议。最终论文、仓库 commit、配置和权重入口必须在阶段 1 单独锁定，本文件不把它们提前写成已复现事实。

## 一、选择标准

本作业是个人项目，硬约束如下：

- 调研近三年目标检测算法，聚焦一个模型的结构和计算原理。
- 在 TT100K 上训练和测试，选择不少于 10 类目标。
- 完成基线、问题分析、验证性改进和实验报告。
- 在基础任务成立后，尽量完成“目标识别 + 交通流量预测”的高阶方案。
- 本机只有 RTX 4060 Laptop 8 GiB，不能把多卡大模型训练作为既定条件。

模型排序同时考虑论文可追溯性、官方代码成熟度、TT100K 迁移成本、单卡训练成本、改进可拆性，以及报告中能否把结构讲清楚。

## 三、主模型建议

### 3.1 主选：YOLOv10-N

建议把 YOLOv10-N 作为阶段 1 的主选，原因不是“官方 AP 更高”，而是：

1. 它有可引用的正式论文和官方 PyTorch 仓库，满足“锁定目标论文与仓库”的方法论要求。
2. 2.3M 参数和 6.7G FLOPs 适合 8 GiB 显存上的短周期基线和单因子实验。
3. NMS-free 结构让“模型结构、推理流程和时延”有明确的报告内容。
4. 参数量小，重量级骨干、剪枝和蒸馏不适合作为本作业第一批改动；改进应优先针对实际错误。

### 3.2 保守备选：YOLOv8n

如果阶段 1 发现 YOLOv10 官方代码在 Windows、当前 Python 或 GPU 环境下无法按文档运行，则切换到 YOLOv8n，而不是在同一会话里临时改框架。切换必须记录原因、原始命令和失败日志。

### 3.3 暂不选择

- 不用 YOLOv3/DarkNet 作为本次主模型：截图里的相关建议可用于理解历史和设计思路，但不满足当前“近三年算法”的重点。
- 不先做 MobileNetV2/ShuffleNetV2 替换骨干：YOLOv10-N 已经是轻量模型，未证明时延是问题前替换骨干会破坏可比性。
- 不在同一轮同时做剪枝、INT8、蒸馏和类别加权：无法拆分收益来源。

## 四、模型结构和计算原理的聚焦点

阶段 1 和报告第二章需要把以下内容讲到能够回答追问：

1. 输入端到特征提取、颈部融合和检测头的张量流。
2. 一致双重分配如何同时提供一对多和一对一监督，以及它为何能减少对 NMS 的依赖。
3. 分类分支与边界框回归分支的输出含义。
4. 分类损失、边界框回归损失和一致性约束的职责，不把总损失下降直接解释成 mAP 提升。
5. 参数、FLOPs、显存、推理时延与 mAP 的取舍，尤其说明 COCO 数值不能替代 TT100K 结果。

## 五、诊断后的改进假设池

以下内容只是候选因素，阶段 3 完成每类 AP、尺寸分桶、混淆和漏检分析后才允许打开其中一个。

| 假设 | 触发证据 | 单因子实现 | 预期观察 | 失败时的价值 |
| --- | --- | --- | --- | --- |
| 长尾类别分类偏置 | 少数类 AP/Recall 明显低，且误分为高频类 | 仅修改分类损失，使用训练集频率计算并裁剪类别权重 | 少数类 AP 改善，总体 mAP 不一定同步提高 | 可说明分类损失权重并非主要瓶颈 |
| 小目标召回不足 | 小尺寸分桶 Recall 明显低，漏检集中在远距离小标志 | 增加 P2 检测层或受控提高输入分辨率 | 小目标召回提升，计算成本上升 | 可说明容量/分辨率与收益的边界 |
| 光照和天气鲁棒性不足 | 合成退化测试集上性能下降显著 | 训练端加入固定的低亮度、噪声、雨雾或局部过曝增强 | 退化测试更稳，干净集可能持平或下降 | 可说明增强并非无条件提升主指标 |

优先级默认是“长尾分类偏置 > 小目标容量 > 天气增强”。如果阶段 3 的证据方向不同，按证据调整，而不是按截图顺序强行执行。

每一个改进实验都必须和同数据、同划分、同输入尺寸、同 epoch 预算的基线比较。只跑一个 seed 时写成“单次探索性结果”。

## 六、高阶拓展路线

高阶目标不改变 TT100K 基础任务的数据定义。可行路线是复用第一次大作业已经核验存在的交通流预测资产，构建模块级原型：

```text
TT100K 图像
  -> YOLOv10-N 检测结果
  -> 类别、置信度、边界框和样本 ID 的结构化 JSON
  -> 计数或场景上下文适配层
  -> PEMS08 交通流序列
  -> TA-iTransformer 预测
  -> 态势展示与误差评估
```

这里必须明确：TT100K 图像与 PEMS08 时间序列没有天然的一一对应关系。适配层只能显示模块接口和离线联调能力，不能宣称完成了真实道路端到端交通态势预测。

启动条件：

1. 基线、错误分析和至少一个单因子实验已经形成可复算证据。
2. 检测模块能稳定输出结构化结果。
3. 流量预测模块能独立加载并产生可复算结果。
4. 在 PPT 冻结前至少留出一个独立工作单元。

若条件不满足，高阶部分降级为系统架构、接口设计和边界说明，不用伪造截图或拼接数字替代实验。

## 七、阶段 0 决策

- 主问题：TT100K 多类别交通标志检测的主要错误机制是什么，一个可单独开关的针对性改动能否在同训练配方下产生可复核变化。
- 首选模型：YOLOv10-N。
- 保守备选：YOLOv8n。
- 初始工程口径：先完成 CUDA smoke test，再测吞吐；不允许 CPU 结果冒充正式基线。
- 高阶门槛：基础检测证据未过阶段 3 和阶段 4 前，不制作带虚假结果的系统演示。
