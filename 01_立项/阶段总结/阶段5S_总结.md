## 一、阶段目标与边界

目标是在基础阶段 2–5 已通过的前提下，把交通标志目标识别与第一次大作业的交通流预测模块连接一次，形成可复算的最小系统闭环。

本次坚持以下边界：

- 不重训检测模型；
- 不重训 iTransformer；
- 不修改检测或预测权重；
- 不把第一次大作业的现有 checkpoint 包装成本次新训练；
- 不因高阶联调挤占基础检测实验；
- 不把模块通信成功解释为真实端到端预测性能。

## 二、实际完成内容

### 2.1 结构化检测输出

复用 `BASELINE-001` 的阶段 3 测试预测事件：

- 6,780 条可用检测事件；

- 不增加额外检测阈值，不重新选择测试样本。

### 2.2 检测到预测的适配器

固定接口规则：

1. 按图像 ID 数值升序排列唯一图像；
2. 等频分为 96 箱；
3. 每箱累计检测置信度；
4. 对 96 个箱做零均值、单位标准差标准化；
5. 用代理曲线替换 PEMS08 测试窗口第 169 通道；
6. 其余 169 个传感器通道保持原值；
7. 输入形状固定为 `96 x 170`。

`image_id_order_proxy` 不是时间映射，JSON 中固定记录 `valid_as_time_series=false`。

### 2.3 预测模块独立运行

复用第一次大作业：

- `PEMS08.npz`；
- TA-iTransformer `sl96/pl96` 源码；
- 已训练 `checkpoint.pth`；
- 60%/20%/20% 数据切分；
- 训练段拟合的 `StandardScaler`；
- PEMS 日周期与周周期时间特征。

checkpoint 以严格模式加载：

- 74 个参数张量；
- 6,434,442 个参数元素；
- missing keys：0；
- unexpected keys：0。

完整 PEMS08 测试段复算结果：

共复算 3,381 个测试窗口、55,177,920 个预测值，差异远小于预注册的 `1e-4` 容差。

## 四、核心结论

### 已确认事实

1. 检测模块已有可机读的结构化输出。
2. 预测模块能独立读取 PEMS08 固定输入，并严格加载旧 checkpoint。
3. 检测代理进入预测输入后，预测输出确实发生变化。
4. 完整 PEMS08 测试指标与第一次大作业参考值一致。
5. 本次没有进行任何模型训练或权重更新。

### 解释边界

- TT100K 图像不是连续时间序列，图像 ID 顺序只用于构造固定长度代理。
- 检测对象是交通标志类别，不是车辆计数或 PEMS08 传感器观测。
- 第 169 通道替换是零重训工程适配器，不是训练好的多模态融合。
- 单窗口注入版 MSE/MAE 略高，但不能作为性能负结果，因为输入本身没有真实时空对应。
- 本次不能声称完成真实端到端交通态势验证，也不能声称预测精度提升。

### 最终定位

阶段 5S 的成果定位为：

> 一个已实际运行、指标可复算、边界透明的“检测计数到流量预测”离线模块级联原型。

该定位满足高阶要求中的接口、模块独立运行和至少一次离线联调，不越过数据对应关系允许的证据边界。

## 五、兼容性异常与处理

旧项目的一键入口会统一导入 Reformer，尽管本次 checkpoint 不使用 LSH/Reformer。直接运行时报缺少 `reformer_pytorch`。

补装解析曾试图把现有 PyTorch 2.0.1+cu118 替换为新的 124 MB 版本，已立即中止，现有 PyTorch/CUDA 未被升级或破坏。

最终处理：

- 新建聚焦推理器，只加载 `iTransformer_TA.py`；
- 为未使用的 Reformer 后端提供显式 import-only 占位；
- 占位类若被实例化会立即抛错；
- 不改旧源码、不改 checkpoint；
- 用完整测试指标复算验证目标执行路径。

该异常和规避方式已写入结果分析，不把旧入口描述为首次直接成功。
