# 阶段 4 预注册：P2 小目标分支

记录日期：2026-11-08。

## 一、单因素与研究问题

**唯一改变因素：** `enable_p2_high_resolution_branch`。

**机制：** 现有 YOLOv10-N 检测头使用 P3/P4/P5。在 640 输入下，部分交通标志到达 P3 检测层时只剩较少像素。将 P3 语义特征上采样到 P2/4，并与骨干 P2 特征融合，再增加 P2 检测头，检验更高空间分辨率是否改善小目标检测。

**可测假设：** 在同数据、同划分、同 40 轮训练配方和同 seed 下，P2 分支提高验证集小目标 mAP50-95 和固定工作点小目标召回，同时总体 mAP50-95 不发生实质下降。

## 二、架构定义

- 基线：`02_代码/阶段4/configs/yolov10n-45.yaml`，仅将 `nc` 固定为 45，结构不改。
- P2 候选：`02_代码/阶段4/configs/yolov10n-p2-45.yaml`。
- 原基线第 0–22 层保持相同顺序和结构，便于从官方权重迁移。
- 新增第 23–25 层：
  1. P3/8 上采样到 P2/4；
  2. 与骨干 P2/4 拼接；
  3. 经 C2f 输出 64 通道 P2 特征。
- 检测头从 P3/P4/P5 改为 P2/P3/P4/P5。
- P2 开关在实验配置层实现：选择基线配置或 P2 配置。

## 四、诊断与验收口径

### 4.1 主指标

- 验证集 `mAP50-95`。
- 验证集 `mAP_small50-95`。
- 固定置信度 0.25 下 small 目标 TP 召回。

测试集只在新模型冻结并完成验证集决策后执行一次。

### 4.2 机制支持条件

单 seed 结果最多写成“探索性支持”。满足以下条件才认为 P2 机制值得继续验证：

1. 验证集小目标 mAP50-95 或固定工作点小目标召回高于基线；
2. 总体验证集 mAP50-95 下降不超过 0.005；
3. 参数量和 FLOPs 增量被明确记录；
4. 收益没有被重复检测、背景误检的大幅增加抵消。

若总体略升但小目标指标不升，不能把收益自动归因于小目标机制。

## 六、启动闸门

正式 40 轮训练前必须完成：

- 基线 YAML 与 P2 YAML 均可构建；
- P2 检测层 stride 为 `[4, 8, 16, 32]`；
- 从官方权重完成仅兼容张量迁移并记录数量；
- 640、batch 8 的一次真实训练 batch 前向/反向与优化器步骤成功；
- 显存峰值不超过 8 GiB 且保留安全余量；
- smoke 日志与 JSON 落盘；
- 不执行 test 推理。

## 七、停止条件

- 模型构建失败或四个检测尺度不成立；
- batch 8 在 640 输入下 OOM；
- loss 出现 NaN/Inf；
- 训练吞吐低到无法在截止日期前完成；
- P2 代码导致基线路径也被修改。

任一停止条件触发时，阶段 4 记录为工程失败或未完成，不重写成通过。
