## 二、已采取的断电保护

1. Ultralytics 每个 epoch 更新 `last.pt`。
2. 后台 checkpoint 监视器会把稳定后的 `last.pt` 复制到：
   `03_实验/P2-001/train/weights/backup/`
3. 每个备份写入 SHA-256：
   `03_实验/logs/P2-001/checkpoint_backup.log`
4. 增加断点续训入口：
   `02_代码/阶段4/stage4_runner.py resume`
5. 增加重启后的自动续训并最终评估脚本：
   `03_实验/脚本/run_stage4_p2_resume.ps1`

正常断电最多只会丢失断电时尚未保存的当前 epoch，不会从第 0 轮重新开始。

## 三、断电前建议

若能在 23:15 左右正常关闭程序或睡眠，优先保留最近一个完整 `last.pt`。不要在 checkpoint 正在写入时强制拔电。

## 四、恢复供电后的操作

先确认没有旧的训练进程，然后在项目目录运行：

```powershell
pwsh -NoProfile -ExecutionPolicy Bypass -File "03_实验\脚本\run_stage4_p2_resume.ps1"
```

续训脚本会：

1. 从 `03_实验/P2-001/train/weights/last.pt` 恢复；
2. 继续到原定 40 个 epoch 或早停；
3. 训练完成后只执行一次 test 评估；
4. 更新 `run_status.json`。

如果 `last.pt` 损坏，则使用 `weights/backup/` 中最近一个 SHA-256 校验通过的完整副本替换；不得直接从头重训并覆盖原日志。
