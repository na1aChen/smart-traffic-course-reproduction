# 阶段 2：官方命令与本机命令对照

记录日期：2026-11-08。

## 一、用途

本文件只记录 YOLOv10-N 官方入口、本机训练入口和参数差异，用于回答“基线是否按官方结构执行、哪些条件因 TT100K 和单卡环境发生了必要适配”。

本文件不替代原始训练日志，也不提前给出模型指标。

## 二、锁定来源

| 项目 | 锁定值 |
| --- | --- |
| 官方仓库 | `https://github.com/THU-MIG/yolov10` |
| commit | `453c6e38a51e9d1d5a2aa5fb7f1014a711913397` |
| 官方模型配置 | `ultralytics/cfg/models/v10/yolov10n.yaml` |
| 权威权重 | Hugging Face `jameslahm/yolov10n`，commit `3b91f578c5b492080f191a26aa35711bb44f608c` |
| 数据 | TT100K 2016 官方包，固定 45 类划分 |

## 三、官方入口

官方 README 给出的训练入口是：

```text
yolo detect train data=coco.yaml model=yolov10n/s/m/b/l/x.yaml epochs=500 batch=256 imgsz=640 device=0,1,2,3,4,5,6,7
```

本课题选择其中最小模型，并将数据替换为 TT100K。官方入口面向 COCO 和多卡大 batch，不能直接作为本机单卡、45 类 TT100K 实验的最终命令。

## 四、本机入口

入口脚本：

```text
02_代码\阶段2\stage2_runner.py
```

实际训练命令：

```text
<PROJECT_ROOT>\02_代码\环境\venv\Scripts\python.exe <PROJECT_ROOT>\02_代码\阶段2\stage2_runner.py train --epochs 40 --batch 8 --imgsz 640 --optimizer SGD --patience 10 --close-mosaic 5 --save-period 5 --device 0 --workers 0 --seed 2026
```

脚本内部仍调用原仓库的 `ultralytics.YOLOv10` 和 `model.train()`，没有修改官方 YOLOv10 训练器、损失函数或检测头。

## 五、逐项对照

| 参数 | 官方入口或默认值 | 本机值 | 是否改变 | 理由 |
| --- | --- | --- | --- | --- |
| 数据 | COCO | TT100K 45 类固定划分 | 是 | 课程任务要求；COCO 入口不能替代目标数据集实验 |
| 模型配置 | `yolov10n.yaml` | 由官方 COCO 权重重建 `yolov10n` 结构 | 否 | 使用同一 YOLOv10-N 结构；仅分类头适配为 45 类 |
| 输入尺寸 | 640 | 640 | 否 | 保持官方检测输入尺寸 |
| epochs | 500 | 40 | 是 | 单卡、课程截止时间和 TT100K 迁移训练预算限制 |
| batch | 256 | 8 | 是 | RTX 4060 Laptop 8 GiB 显存限制；训练日志实测峰值约 1.9 GiB |
| device | 8 张 GPU | `0` | 是 | 本机只有一张 GPU |
| 优化器 | 官方命令未显式指定 | SGD | 是 | 固定优化器以便基线可复算；使用仓库内 SGD 默认动量和权重衰减 |
| 初始学习率 | SGD 默认 `0.01` | `0.01` | 否 | 未针对验证集手工调参 |
| AMP | 默认启用 | 启用 | 否 | 已通过环境烟测；降低显存并保持官方混合精度路径 |
| seed | 官方命令未显式给出 | 2026 | 是 | 固定划分、训练和验证随机性，满足复算要求 |
| deterministic | 官方命令未显式给出 | 启用 | 是 | 提高本机可复算性；可能略降低吞吐 |
| workers | 官方命令未显式给出 | 0 | 是 | 避免 Windows 多进程读取器带来的额外故障面 |
| patience | 默认 100 | 10 | 是 | 在固定 40 轮上限内允许验证集早停 |
| close_mosaic | 默认 10 | 5 | 是 | 40 轮预算下保留最后 5 轮关闭 Mosaic 的稳定阶段 |
| 验证划分 | COCO 固定验证集 | TT100K 从清洗后官方 train 固定派生 10% | 是 | 官方 test 只用于最终评估，不能参与早停或选模 |
| test 使用 | 最终评估 | 仅在 `best.pt` 固定后评估一次 | 否 | 遵守训练、验证、测试职责隔离 |
| test `max_det` | 验证器默认值 | 100 | 是 | 与标准 COCO 的 `maxDets=100` 对齐，便于内置指标与独立复算互证 |

## 六、权重进入训练链路的方式

阶段 1 的权威权重是本地 Hugging Face 目录 `02_代码\权重\yolov10n_hf`。当前仓库版本的 `YOLOv10.from_pretrained()` 生成空 `ckpt` 包装对象，直接调用 `train()` 时不能稳定携带原权重进入重建后的 45 类训练器。

为避免“看起来加载了预训练权重、实际从头训练”，运行器执行以下步骤：

1. 分别加载本地 Hugging Face 权重和 `02_代码\权重\yolov10n.pt` 兼容载体。
2. 对 595 个张量逐项检查键名、形状、数据类型和数值。
3. 只有全部完全相等，才允许进入训练。
4. 训练日志显示 `Transferred 493/595 items from pretrained weights`，差异主要来自 80 类分类头和随类别数变化的相关层。

原始校验见：

```text
01_立项\阶段2_证据\权重等价性校验.json
```

## 七、阶段 2 的结论边界

- 本阶段验证的是 YOLOv10-N 官方结构在 TT100K 45 类固定划分上的迁移训练，不是论文 COCO 表格的逐位复现。
- 与论文的 epoch、batch、数据分布和类别集合不同，因此不能用论文 COCO 的 AP 数字直接要求本实验达到同一数值。
- 训练、验证和测试职责固定后，任何配置调整都必须作为新的实验 ID 记录，不能覆盖 `BASELINE-001`。
- 最终测试集指标只从验证集选出的 `best.pt` 计算；测试集不参与优化器、学习率、早停或改进方案选择。
